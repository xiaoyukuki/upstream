## 1. 项目是什么

- Godot **4.6.1**（mono 版，但全部用 GDScript 写），2D 横版解谜平台游戏，GL Compatibility 渲染，**第一章原型**阶段。Windows 开发，工作目录 `D:\Godot\Ups\upstream`。
- **核心机制「移动即冻结」**：玩家按住左右方向键移动时，整个世界进入冻结（玩家、相机、UI 之外的一切停住）；玩家松手静止时，时间恢复流动。全部谜题围绕这条规则设计。
- 玩家是唯一不受冻结影响的对象（设定上是"时间旅行者"）——这是整个机制成立的前提。

## 3. 时间系统怎么实现

- `TimeManager`（autoload）只累计世界时间；每个构件挂一个 `TimeReceiver`，每帧读「门控 delta」——冻结期间该值为 0，构件因此自然停住；解冻后从停住的地方继续。**连续性靠算术性质保证**（开度是累计时间的纯函数），不用 tween/seek 那种恢复瞬间会跳帧的路子。按世界钟走的那一类目前有四个例外：刷卡门（D40 / D41）、死亡那一拍（D42）、祭坛授予那一拍（D44 / D61）、以及**被时间锚吸住的构件（D68）** —— 最后这条不是"不吃时间"，而是**换了一条时间源**：它的 `TimeReceiver` 被换成 `TimeAnchor` 的泵，跟的是玩家手上有没有方向，而不是世界钟。刷卡门不挂 `TimeReceiver`、完全不消费世界时间，因为「带卡走近 → 认卡 → 演一拍退场」是一次性后果而不是要玩家利用的节拍；死亡与祭坛那两拍同理，都跑在引擎固定物理步长上，冻结中也照跑 —— 区别是**刷卡门那拍会顺手锁住玩家水平输入，死亡那拍把人钉在原地靠的是"尸体不再走路"而不是锁**，而**祭坛那一拍（D61 重做，D44 那版"不锁移动、不碰 `TimeManager`"两条已整块推翻）现在既锁移动、又在爆发那一帧用 `release_frozen_override` 反向的那条入口真的把世界钉住约 1.25 s**：人被举起来，方向键不掐就会把他从演出里拽走。**还有一条更上游的路（D59）**：世界钟那只纯装饰构件既不挂 `TimeReceiver` 也不自己累加 delta，而是把 `TimeManager.elapsed_world_time` 当**纯函数**读，于是它与门控 delta 数值等价、却天然共用 `reset_state()` 那个零点（换关/回灌后不漂）。**D69 的相位器件把"默认跟世界钟"这条基线落了地**：它们平时就挂普通 `TimeReceiver` 吃世界钟，被锚吸住时**同一根** `TimeReceiver` 被换成锚的泵 —— 器件里没有一行"我被吸住了"的判断，所以"平时受世界钟调控"不是要额外写的分支，是它们的默认形态。
- **进入冻结态有两条来源（D42 起）**：玩家的移动意图，与 `TimeManager.set_frozen_override(true)` 那道**强制钉住**（死亡那一拍在用）。钉住与能力开没开、与松没松手都无关，且钉住期间意图整条通道静音（否则死前按着方向键、死后松手会把刚钉住的世界放回流动）；两条来源写的都是同一个 `current_state`，所以冻结滤镜（D46 之后是一层 CRT）、门控 delta、调试面板全都自动读到同一个事实。只有 `reset_state()`（每个关卡实例 `_ready()` 必调）会清掉那道锁。**D61 为它加了第二条松手入口 `release_frozen_override(moving: bool)`**：现有那条 `set_frozen_override(false)` 只清开关、把"变回流动"留给意图通道，而意图通道在 `not is_ability_enabled` 时整条静音 —— 那恰好是玩家**第一次**拿到能力的当口，于是"世界停在 FROZEN、再没人负责解开"；事后补一次 `notify_movement_intent()` 也不行（handler 只在边沿上报，此刻它认为自己已经报过了）。新入口把当前意图原样带进来、直接落状态：`FROZEN if (is_ability_enabled and moving) else FLOWING`。
- 绝对不用 `Engine.time_scale`。
- 玩家、相机、UI 用真实 delta，永远照常运行；玩家动画在冻结期间照常播放（这是"玩家例外"最直观的可读性）。

## 4. 构件与摆图工具箱

- 全部构件带 `@tool`：检查器里改参数，编辑器预览立刻重画。
- 原点约定（摆图最容易错的点）：**地形按左上角摆，其余构件全部按"贴着地面的那一点"摆**（门的原点=门洞底边中心，按钮=面板底边中心……）。**例外四处**：电棒=光束中心、残影踏板=喷嘴口（第一格顶边）、活塞踏板=**收回态的前缘中点**（横着伸的那一块因此要把原点抬到地面上方半个方块，否则底边陷进地里；**D63 那档反向活塞不挪这条约定** —— 摆的还是洞口那一点，变的只是静止时身子停在对岸）、**坠落带=顶边中心**（D52，全工具箱唯一向下生长的构件：要摆的量只有"顶边线压在哪条 y 上"）。**D69 的两件相位器件不开新例外**：`phase_panel` 原点 = 底座中心、`phase_shuttle` 原点 = A 停靠点块心，都归"块心"那一族（与移动方块同读法）—— 面板块底在原点**下方** 8 px，底座坐地上就填 `y = 地面线 − 8`，要平射打中胸口线就抬到 `y = 地面线 − 18`。网格 32 px。
- 碰撞层：1=地形，2=玩家，4=时间固体，8=感应。玩家 mask=1+4。
- **Door（升降门）**：卷帘式，顶边固定底边上升，开度是门控时间的纯函数（碰撞体与画出来的门扇永远重合）。`trigger` 属性指向任意发 `pressed_changed(bool)` 的节点（按钮/感应区都行），检查器里直接拖拽接线，编辑器会画一条辅助线。**接触让位（D21）**：门扇下行途中与玩家接触时就停在接触位置，不把人推开；玩家离开后自动继续关闭。玩家可以拿头顶住门——这是有意保留的玩法。
- ButtonPlate（按钮面板，冻结期间不弹起）、SensorZone（触发区，人走开立刻松开）、Pendulum（纯演示无碰撞）、MovingBlock（往返平台）、AbilityAltar（一次性能力祭坛，静止时刻才生效；**踩上之后那一拍 5.0 s 的演出归 `Player` 演，不归构件**，见 D61 —— 祭坛只发 `ability_granted` 并把时长递过去）。**摆图新增一条要紧事（D61）**：那一拍把人垂直举起 48 px = 三格，所以**祭坛上方三格之内不许有顶**；有顶他就撞停在那儿（不攒高度也不穿过去，但看起来就是"卡住了"）。**D62 那一拍演完时 `LevelBase` 自动存一次**：把玩家当时落脚的那一点写进 `respawn_position`，并且**不给灯** —— 祭坛不发 `checkpoint_reached`、不提供 `claim()` / `release()`，旧那台当场熄灭、`respawn_marker` 整个键擦掉（用户裁定：「只写重生位，不给灯」）。跳着撞进触发带的那一次不存（写进去的是一格空气）。
- **不是每个构件都有契约面（D59 起）**：`clock.tscn` 是世界钟，全项目第一个**纯装饰构件** —— 零碰撞体、零信号、零 `run_state`、`LevelBase` 不认识它，拖进 `Objects/` 就算完事。它的"接线"只有一条：亮格是 `elapsed_world_time` 的纯函数，所以世界冻着它停。别顺手给它加回执（D4① 已裁：不加运行灯、不变暗、不闪），也别照它的样子把别的表现塞进构件契约里。**D76 的假墙盖是这一族的第三件，时基却反过来**：`cave_cover.tscn` 的不透明度只由"玩家身体中心到 `Mouth` 的距离"决定（位置纯函数），横按方向键冻世界时它**照样淡出** —— 照时钟揭幕会在玩家正朝它走的时候停住。它没有碰撞、不挂 `TimeReceiver`、不发信号；摆法是"在 `Terrain` 下 `position` 留 (0,0)、洞口那几格刷墙的 `solid` 格、放一个 `Mouth`"，`verify_kit` 逐格核"盖的是不是墙的实心格"（背景 `wall_fill` 与实心格同一张图集却是两套材质，逐字节差 768/1024）。**D77 的梦泡是第四件表现件，也是第一件"有契约面但不属于器件族"的**：它发一根 `completed`、被 `LevelBase` 自动连（另三件都零信号），却仍不挂 `TimeReceiver`、不进 `anchorable`、不认 `run_state`，时基与 D76 同侧（吃引擎物理步长，不读世界钟 —— 这一拍掐着输入，世界照常流动）。所以那三族的禁令**不能整抄**：`clock`/`ecg` 是"必须读世界钟"，`cave_cover`/`dream_bubbles` 是"不许读世界钟"，而只有 `dream_bubbles` 允许发 signal —— `verify_kit` 里三条禁令各自点名，抄错族就红。
- **相位器件（D69）：一关摆几个、零接线、只吃时间** —— `phase_panel.tscn`（中间 32×16 底座**永远实**，两侧桥面按相位现形；`panel_size` 控制桥面，底座不动）+ `phase_shuttle.tscn`（48×16 实心踏板在 A/B 之间整块瞬移，`offset` 是 B 相对 A 的位移、跟着节点旋转）。两个导出项 `period` / `duty` / `phase` 住在共同地基 `components/clock_device.gd`：`period ≤ 0` = 恒开、`duty` 0/1 = 恒关/恒开，`phase` 是开局落在哪一格（编辑器里就按它预览）。**它们只吃时间、不接任何触发源**（没有 `trigger`、没有 `triggers`、零信号），所以玩家要控制它们只能靠 D68 那根锚：**平时受世界钟、被锚吸住时反过来跟手**。**变实/换位前会问一次物理世界**（玩家或别的 time_solid 占着目标位置就停在旧状态、让开那一帧接着变，不把人挤开）；这与门那套"接触让位"不是一回事。**摇表成本**：默认 `period 2.0 / duty 0.5` 最坏 1.0 s，跑速 260 px/s ⇒ 260 px，短于锚的 320 px 射程。两件都进 `anchorable` 族（可被吸），层 4 / mask 0。皮肤是 `_draw()` 现算、走 `WorldClock.COL_*`，没有 PNG 零件。
- 新关卡：复制 `level_template.tscn`/`level_template.gd` 起步；接线优先写在场景里（拖属性），关卡脚本只处理场景表达不出来的逻辑。
- **关卡内部的摆法（D65，模板就是按用户 `level1.tscn` 的实际组织法重写的）**：地形只有 `Terrain` 下那三层瓦片（没有灰盒）；`Objects` 下**给"一关摆好几个"的那一族开文件夹**，文件夹名跟构件名、**触发源与它驱动的那件同文件夹**（接线因此永远一跳 `../ButtonPlate`）；**一关只出现一次的构件直接挂 `Objects`**（`altar_path` / `goal_path` 两个默认值钉着这两条，套了文件夹忘改导出项 = 静默失效）；零契约的装饰挂场景根。文件夹用 `type="Node"`（没有 `position` 这个属性），而三个根容器 `Terrain`/`Objects`/`Triggers` **必须停在 (0,0)** —— `verify_kit` 对所有关卡钉这一条。
- **D28（2026-09-20）**：祭坛授予能力（D16）与终点区收尾（D18）已下沉到 `LevelBase`，按约定摆 `Objects/AbilityAltar` / `Triggers/GoalZone` 就自动生效，新关零代码；接线一律 `@export_node_path`（默认路径 + 解析不到静默跳过）。`verify_kit` 改为**自动发现** `scenes/levels` 下的关卡、且不再钉任何摆位坐标（挪祭坛不再 FAIL）。

## 8. 协作约定

- 实现前先产出**编号设计决策**（D 系列），用户确认后再写代码；用户自带的参考代码不具约束力，发现问题要指出而不是照抄。
- **摆图由用户自己做**；AI 的职责是摆图工具箱（@tool 预览、原点约定、模板、手册、守门命令）。用户报问题时，先怀疑工具箱再怀疑玩法逻辑。
- 试玩与手感判断归用户。
- 已知坑：改带 `class_name` 的脚本后要**重启编辑器**；"指向另一个节点"的导出项一律用 `@export_node_path` 不用 `export(Node)`（4.6 里 Node 槽不会被还原成节点引用）。
