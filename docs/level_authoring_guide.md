# 关卡搭建手册（瓦片地形 + 构件套件）

面向"我来摆图"的工作流。读完这一页就能开新关，不需要再翻 `m2_level_01_layout.md`。
所有数值都是**实测**常数，不是估的。

---

## 0. 开一关的最短路径

1. 复制 `scenes/levels/level_template.tscn` → 改名 `level_02_xxx.tscn`；复制 `level_template.gd` → 同名。
2. 场景根选中 → 脚本指向新的 `.gd`。
3. 地形在 `Terrain/Tiles` 层**刷瓦片**（见 §12）。模板自带的地面与两面侧墙已经删掉了（D65）：地形从第一笔就是瓦片，不再有"先摆盒子后来换成砖"那道返工。`Terrain/WallFill` 与 `Terrain/Decor` 两层刷背景贴面与装饰，都无碰撞。`platform.tscn` 这件构件还在（旧关与临时挡块在用），只是不再出现在模板里。
4. 在 `Objects` 下摆构件（门/按钮/钟摆/移动方块/祭坛/触发区/尖刺/电棒/钥匙卡与刷卡门/存档点/坠落带/世界钟/相位面板/相位穿梭块）。**一关要摆好几个的那一族，单独开一个文件夹**（D65）：文件夹名 == 这一族里被驱动的那件构件场景名（`Spikes`、`PistonBlock`、`KeyDoor`），触发源与它驱动的那件**同文件夹**，于是接线永远是一跳 `../ButtonPlate`。摆一个的就不开文件夹，多套一层只在拖引用时多绕一步。**一关只出现一次的构件直接挂 `Objects`**：`LevelBase.altar_path` 的默认值就是 `Objects/AbilityAltar`，套了文件夹又忘了改导出项，这关会静默地没有祭坛（终点区 `goal_path` 同理，固定叫 `Triggers/GoalZone`）。文件夹本身用 `type="Node"` 而不是 Node2D —— 裸 Node 没有 `position`，下面第 5 条那个坑在类型上就不成立。世界钟（D59）是**纯装饰**：拖到场景根下面就行（模板就这么放的），不进 `Objects`、不参与任何接线与判定。**心电监护屏（D75）是这一族的第二件，摆法一字不差**（拖到场景根下即可，`beat_period` 是唯一旋钮）。
5. **分组容器必须停在 (0,0)**（D65）：根上的 `Terrain`/`Objects`/`Triggers` 一旦带 `position`，它下面整块构件被平移，编辑器里看着压住 `y = 0` 的按钮运行时其实沉在别处 —— 这种偏差在编辑器里看不出来，而 §2 那张表的全部读数已经不可信了。verify_kit 对所有关卡钉这一条。
6. 配接线：把按钮拖到门的 `trigger` 属性上（模板里那扇示例门已经接好了，改指向即可）；活塞那块是 `triggers` **一列**，一台一格、拖多少台都行（任一台按下就伸出，D60）。摆图期间**不需要写关卡脚本**；只有场景表达不出来的逻辑（比如"两台都踩着才伸"这种 AND、或者门由别的条件管）才回到 `.gd` 里写，并留空让脚本来调 `set_out()` / `set_open()`（留空会被 §12 那条守门报成漏接线，这是有意的：关卡里每一块都该说得出谁在驱动它）。
7. **祭坛、终点区、危险物与存档点都不用写代码**（D28/D38）：按约定摆 `Objects/AbilityAltar` 与 `Triggers/GoalZone`，`LevelBase` 自动接 —— 踩祭坛触发 D16 静止即启，踩终点触发停手后重开；摆进来的尖刺/电棒/刷卡门自动接「碰上即死」，存档点自动接「踩上即存」，全部零接线。**坠落带 `fall_zone.tscn` 也是同一族**（D52）：把它横在关卡底部，掉出世界就算死、回最近那台存档点 —— 一关不摆就是"没有底"，而那条路上没有任何兜底，人会一直落到别的东西上（**别忘了摆**）。挪了位置就在检查器改根节点的 `altar_path` / `goal_path`；本关不要祭坛就把那一项清空。**存档点任何时候只有一台亮着**（D51）：踩新台就把旧的顶回 idle 皮，往回踩旧台则把激活搬回来 —— 一关摆几台都行，亮着那台说的就是"现在死会回到这儿"。**第一次获得能力那一刻会自己存一次**（D62）：那一拍演完时重生位换到他落脚那一格，同时把亮着的那台顶灭、身份键抹掉 —— 从那一刻起到他踩上下一个存档点之间**全场一台都不亮**，这是裁定不是漏做（祭坛刻意不属于存档点那一族，见 §5 与 §8a）。
8. 填根节点的 `camera_limits`。
9. 跑：`main.tscn` 的根节点上把 `level_scene` 指过来（保留冻结滤镜与调试面板），或直接 F5。

模板自带玩家、`PlayerSpawn`、三层瓦片空地形、一个终点 `GoalZone`（踩到 → 停手 1.5 s → 自动重开）、一条 `FallZone`，以及**每族一个接线样品**：门+按钮、活塞+按钮、存档点、钥匙卡+刷卡门、尖刺、鸭子、残影踏板、祭坛、世界钟、心电监护屏（后两件是纯装饰，挂在场景根上，D75）。样品排成一行只为把每族的接法与原点读法一眼摆清，**不是合法关卡布局**（D65）—— 复制完就把它们挪到自己关卡该在的位置，或照样品再复制出实例。

死亡与重开是两条路（M5，D31）：碰危险物 → 重载本关，**保留**存档点与祭坛进度，钥匙卡、刷卡门、机关相位全部归位；R 键与终点重开 → 同样重载，但**清空**进度。

## 1. 坐标系：只有两条要记

- **y 轴向下为正**，所以"往上跳"是 y 变小。地面线用 `y = 0`，往上的平台写负值（`-128` 表示地面以上 4 格）。
- **网格 32 px**。地形尺寸填 32 的整数倍，位置也尽量落在格线上，相机与高低差才不会被半个格子毁掉。瓦片本身是 16 px，但**设计网格仍是 32 px = 2 格**：本节与 §8 的所有约束照旧，32 的边界落在偶数格线上。

## 2. 原点约定（摆错就是穿模或悬空，这一张表最要紧）

| 构件 | 节点原点在哪 | 生成方向 |
|---|---|---|
| `platform.tscn` | **左上角** | 向右下生长 |
| `door.tscn` | **门洞底边中心**（贴地） | 向 `-y` 生长 |
| `button_plate.tscn` | **面板底边中心**（贴地） | 向 `-y` 生长 |
| `ability_altar.tscn` | **台座底边中心**（贴地） | 向 `-y` 生长 |
| `sensor_zone.tscn` | **触发区底边中心** | 带心由 `band_centre_y` 决定（默认在原点上方 15 px） |
| `pendulum.tscn` | **悬挂点** | 摆锤在 `rod_length` 处 |
| `moving_block.tscn` | **方块几何中心 = 行程起点** | 行程终点 = 原点 + `travel_offset` |
| `spikes.tscn` | **尖刺带底边中心**（贴地） | 向 `-y` 生长（牙高 14）；贴顶倒刺 = 同一场景转 180° |
| `electric_bar.tscn` | **光束中心**（三处例外之一，可浮空） | 带子关于原点对称展开；竖电闸 = 旋转 90° |
| `key_pickup.tscn` | **底座底边中心**（贴地；D55 起卡坐在座上，原点仍是压住地格线那一点） | 拾取带带心 −15，与按钮同族 |
| `key_door.tscn` | **门洞底边中心**（贴地） | 向 `-y` 生长（与 `door.tscn` 同约定） |
| `checkpoint.tscn` | **台座底边中心**（贴地） | 向 `-y`（终端 32×12） |
| `afterimage_emitter.tscn` | **喷嘴口 = 第一格的顶边**（第二个例外，浮空在天花板下） | 链向 `+y` 落，落到 `reach` 为止；节距 = `fall_speed × emit_interval` |
| `piston_block.tscn` | **收回态的前表面中心 = 洞口线在中轴上那一点**（第三个例外） | 身子整块在原点背后；沿 `travel_offset` 主轴伸出，伸出多少就露出多少 |
| `fall_zone.tscn` | **顶边中心**（第四个例外，且**方向反了**） | 向 `+y` 生长（`depth` 往下给） |
| `phase_panel.tscn` | **底座中心**（“块心”那一族，与移动方块同读法，不新增例外） | 底座 32×16 关于原点对称，桥面向左右各展 `panel_size.x / 2`、上沿与底座齐平；**块底 = 原点 + 8 px** |
| `phase_shuttle.tscn` | **停靠点 A 的块心**（场景里摆下去那一点就是 A） | B = A + `offset`（跟着节点旋转走），整块瞬移、没有中间位置 |
| `ecg_monitor.tscn` | **盒子中心**（D75，"块心"那一族，与移动方块 / 两件相位器件同一读法，不新增例外） | 本体 `x ∈ [-24,23]`、`y ∈ [-16,15]`；它是**挂在墙上**的仪器，没有"压住地格线"那一点 |
| `collectible.tscn` | **底座底边中心**（贴地，D54） | 向 `-y`（鸭 + 座外接框 14×16）。**拾取带不走 §3 那条"带心抬半个盒高"的脚带**：它是外接框外扩 4 px（22×24，带心 −8），因为鸭子站在台子上、动词是"走过去擦到"而不是"站上去" |
| `player.tscn` | **身体中心**（脚底在原点下方 15 px） | — |
| `Tiles` / `Decor` / `WallFill`（TileMapLayer） | **cell (0,0) 的左上角 = 层节点原点** | 向 +x / +y 逐格生长 |

一句话记法：**地形按左上角摆，其余全部按"贴着地面的那一点"摆** —— 例外四处：**电棒**（原点 = 光束中心，因为它要原地旋转，底边中心对一根浮空棒没有意义）、**残影踏板**（原点 = 喷嘴口 = 第一格的顶边，因为它是从天上往下掉的：拿底边当原点的话 `reach` 要往负方向填，而且节点一挪整条链跟着跳）、**活塞踏板**（原点 = 收回态的前缘，因为"伸多远"和"洞口在哪"必须各管各的：前缘的投影恰好等于原点的投影，让位算式因此少一项）与**坠落带**（原点 = **顶边**中心 —— 全-kit 唯一往下生长的那一个。这张网唯一要摆的量就是"顶边线压在哪条 y 上"，原点落在线上才拖得走；深度由 `depth` 往下给，不必再算半个高度）。瓦片层同理按左上角：cell (0,0) 的左上角就是世界 (0,0)，所以地面线 `y = 0` 正好是第 0 行的上边，往上一格是 `y = -16`。

**活塞踏板还多一条：行程是横着的那一块，原点得抬到地面上方半个方块**（默认 `block_size = 64` → 32 px = 一格）。原点在前缘的中点，所以身子关于中轴上下各占一半 —— 贴着地面摆的话，收回态那截身子的下半截会露在地面以下。竖直伸出的那块不用抬：原点就落在地面线上。

**两件相位器件（D69）走"块心"那一族**：`phase_panel` 的原点是底座中心（块底在原点下方 8 px），`phase_shuttle` 的原点是 A 点块心。想让面板的底座**坐在**地面上就填 `y = 地面线 - 8`（块顶 = 地面线 - 16）；想让站在同一层的玩家**平射**打中它，抬到 `y = 地面线 - 18`（块身跨过胸口线 —— 时间锚的射线从胸口出，贴地摆平射会从顶上 2 px 擦过）。鼠标瞄准是任意方向，贴地摆也能俯射，抬不抬取决于这一关要不要它先挡路。

## 3. 触发带为什么以前会坑人

`Area2D` 判的是**玩家碰撞盒**是否重叠，而玩家贴地站着时碰撞盒中心在地面以上 **15 px**（碰撞盒 20×30）。手写 `CollisionShape2D` 贴着地面画，玩家走过去就"没反应"。

现在这个偏移除掉了人肉记忆：`Player.COLLISION_HALF_HEIGHT = 15.0` 是唯一来源，所有传感器的带心默认就是 `-15`。改玩家碰撞盒尺寸时只改这一个常量，构件会跟着重算。

空中触发带（比如要判"玩家跳过了某条高度线"）把 `band_centre_y` 填 `0`，带子就以节点原点对称展开。

## 4. 碰撞层（照抄，别新发明）

| 层 | 号 | 谁在这层 | 谁的 mask 读它 |
|---|---|---|---|
| `terrain` | 1 | Platform、`Tiles` 层（TileSet 物理层 0） | Player |
| `player` | 2 | Player | Door、MovingBlock、所有传感器 |
| `time_solid` | 4 | Door、MovingBlock、PistonBlock、残影踏板链（冻结时）、**PhasePanel（底座 + 桥面）、PhaseShuttle**（D69） | Player（mask 5）、时间锚射线（`HIT_MASK = 1\|4`）、`ClockDevice` 的占位查询（`CLEAR_MASK = 2\|4`） |
| `sensor` | 8 | 所有 Area2D | —（`monitorable = false`，纯观察者） |
| （无层） | 0 | 危险物判死区（Spikes / ElectricBar / KeyDoor 的 Reader、**FallZone 坠落带**，D52） | 自己 `mask = 2` 读玩家 |

Player `mask = 5`（terrain + time_solid）。传感器一律 `layer = 8, mask = 2, monitorable = false`（钥匙卡、存档点、**彩蛋收集物（D54）**也在 sensor 层 —— 它们就是纯传感器。彩蛋刻意**不走**危险物那条 `layer = 0`：它不判死，而上实体层会把"鸭子站在台子上"变成一块能踩的台阶）。

**危险物判死区一律 `layer = 0`、`mask = 2`、`monitorable = false`（构件已内置，别手动改层）**：刻意不上任何层 —— 上了 sensor 层，玩家的起身净空查询会把一根通电的棒读成「头顶是空的」（D29 与 D27 交叉核对那条硬约束）。电棒要挡路的形态走 `time_solid`：内挂的 Blocker 子节点通电时才上 layer 4，净空查询读得到它，这是对的。

## 5. 构件速查

**摆位之外还有一条组织约定（D65）**：一关要摆好几个的那一族在 `Objects` 下开一个文件夹，文件夹名 == 这一族里被驱动的那件构件场景名；**触发源与它驱动的那件同文件夹**，于是 `trigger` / `triggers` / `key` 这些接线永远是一跳 `../ButtonPlate`（一列按钮指多台活塞也算这一条，D60）。一关只出现一次的构件（祭坛）直接挂 `Objects`，别套文件夹 —— `altar_path` 的默认值就是那条路径，套了而忘了改导出项会静默没有祭坛。三条理由与完整清单在 §0 第 4 步；容器位移那条在 §11。

| 构件 | 关键导出项 | 对外信号 | 摆的时候注意 |
|---|---|---|---|
| `platform.tscn` | `size`、`color` | — | 尺寸改了碰撞体自动跟上 |
| `door.tscn` | `height`（门洞净高）、`width`、`open_time`、`trigger` | `open_changed` | 卷帘式：顶边固定、底边上升。`height ≥ 40` 才过得了人。**没有调色导出项**（D25：立绘是 `assets/props/` 的平铺零件 + 固定调色板，明度对比是量出来的契约）。**`trigger` 里填谁，这扇门就被谁开**：点属性右侧的文件夹按钮选，或从场景树直接拖一个带 `pressed_changed(bool)` 的节点进来（按钮、触发区都行）。留空 = 归关卡脚本用 `set_open(bool)` 驱动。编辑器里会从门底画一条橙色线连到触发源，运行时不画 |
| `button_plate.tscn` | `width`、`sensor_height`、`press_depth` | `pressed_changed(bool)` | 冻结期间玩家走开**不会**松开，解冻当帧才弹起（画面自洽）。凹槽只有 8 px 深，`press_depth` 超过 8 画面就夹住了，调它没有意义。**没有调色导出项**（D25，同上） |

## 6. 关卡脚本能碰什么、不能碰什么

- **玩法连线优先写在场景里**（D20）：按钮开哪扇门 = 把按钮拖到门的 `trigger` 上，不用来关卡脚本写。编辑器里门会画一条橙线连到触发源，没接线的门就是光秃秃的。关卡脚本只负责"这扇门由别的条件管"这类场景里表达不出来的逻辑 —— 那种时候把 `trigger` 留空，脚本来调 `set_open()`。
- **D16 与 D18 已经不用写了**（D28）：祭坛授予能力与终点区收尾都下沉到了 `LevelBase`，摆对节点即可。想要不同的节奏改根节点上的导出项：`ability_enable_timeout`（默认 2.5 s）、`goal_restart_delay`（默认 1.5 s，填 0 表示不自动重开）、`death_time`（默认 0.55 s，D42 那一拍有多长，纯节奏、与谜题无关，填 0 就退回"点名当帧换场景"）。想加自己的日志/演出，覆写 `_begin_ability_sequence()` 与 `_on_ability_enabled(reason, wait)`。
- 可以：构件信号、`TimeManager.set_ability_enabled(bool)`、`TimeManager.reset_state()`、`TimeManager.elapsed_world_time`、`LevelBase.restart_level()`。
- 不可以：直接改构件内部、用 `Engine.time_scale`、绕过 `TimeReceiver` 自己计时。构件的 `_process/_physics_process` 一律读 `TimeReceiver.get_physics_delta()`，冻结时那个值是 0。
- **别把子类方法起成基类被 `connect` 的那个名字**：GDScript 方法默认虚调用，子类同名会**覆盖**基类。比如终点日志要叫 `_log_goal_reached`，不能叫 `_on_goal_body_entered`（那是基类连的名字，覆盖后自动重开直接失效）。
- 关卡自己的等待/节奏计时用 `_process` 的真实 delta，不要用门控 delta —— 否则"没松手 → 世界停 → 计时也停"是个死结。

## 7. `camera_limits` 怎么填

视口 1280×720 @ zoom 2 → **一屏可见世界 640 × 360 px**。

`camera_limits = Rect2(左上角 x, 左上角 y, 宽, 高)`，且 **宽 ≥ 640、高 ≥ 360**，否则相机在里面顶来顶去。
留空（`size` 为 0）= 沿用 `player.tscn` 里的兜底 limits。

例：世界 x ∈ [-96, 1984]、y ∈ [-416, 96] → `Rect2(-96, -416, 2080, 512)`。
经验：左右各比世界边界多留 96 px，底部比地面线多留 32~96 px（掉下来时不至于看到世界外）。

3. **坑深 ≤ 96 px** —— 玩家豁免时停，冻结中仍受重力；掉进跳不出来的坑 = 死局（96 ≤ 136 ✓）。
4. **可通行缝隙 ≥ 40 px** —— 30 px 身高 + 10 px 余量。门洞、门半开时下方的缝都按这条卡。
   **蹲着通过时 ≥ 25 px**（D27：蹲伏盒 15 px + 10 px 余量）。瓦片世界一格 16 px，刷不出 25，所以**瓦片地形里不存在"只能蹲着过"的缝** —— 这一条只在**门半开**那种连续可变的缝上才起作用。

美术比碰撞盒**宽 12 px**（左右各 6）且**矮 5 px**。宽是故意的：40 px 的缝看上去比实际更紧，玩家会以为过不去而实际过得去。矮那 5 px 是「扁」造型的代价 —— 盒顶会露在美术之外，但第一章最小可通行开口 40 px，这 5 px 在任何真实通道里都碰不到。摆窄缝时按**视觉**留余量，别按 20 px 的碰撞盒算；跑动与压扁帧最宽到 34 px，40 px 的门洞在动起来只剩 3 px 余量。

门的时间账：`open_time = 0.5` + 解冻缓冲 `0.08` → 松手后 **0.58 s 关严**。想让玩家"来不及"，只要让"跑过去的时间 > 0.58 s"，即按钮到门 **> 151 px**；引导关用了 432 px（1.66 s）。
门落下来压到站在门洞里的玩家时会**停在他的头顶**（D21），不把他横弹出去，人一走开就续收到关严。摆图侧三条推论：

1. 玩家可以拿头顶住门，这条不打算禁。
2. 被顶住时留下的缝约 30 px，小于站立所需的 40 px —— 不冲突，因为他离开那条缝的过程必然在移动、时间必然冻着。
3. **D27 之后这条缝变成可以蹲着钻过去**（30 ≥ 25）。而且蹲在门正下方会被锁在蹲姿：头顶是门就起不来，也跳不起来，只能横着挪出去（移动 = 冻结，门不追）或等按钮再按下让门上行。不会永久卡死，但**门 + 低矮处**可以做出这种锁定，摆图时要知道。

### 8a. 危险物、存档点与祭坛的硬数（M5，出自 D34/D35/D38/D62/D63/D64）

先记一条总法则（D38「接触即判」）：**伤害、拾卡、认卡都不吃世界时间 —— 冻结期间照样发生**；要走时间的过程（电棒相位、按钮门行程）才吃门控 delta。所以「冻住 = 无敌」不成立：冻在通电相位的棒照样咬人，冻在断电相位就是白送的通道。**刷卡门是这条法则走得最远的一个**：判据与退场都不吃世界时间（D40），而退场那一拍（D41）除了不吃世界时间，还**顺手把玩家的水平移动也锁住同样长的时间** —— 这是全项目唯一一处会按住玩家输入的地方，只掐左右与起跳，重力、蹲伏、冻结意图一概不碰，演完自动还回去。摆位时按「玩家会原地站住 0.45 s」来估后续机关的余量。**死亡现在也是一拍**（D42）：点名之后人不立刻消失，而是停在死处收缩 + 爆裂 0.55 s（`death_time`，关卡根上调），这一整拍里**世界被强制钉在冻结里**，冻结滤镜跟着上（D46 之后那一层是 CRT，不是灰纱），演完才回存档点 —— 摆图时按「尸体会在死处占住 0.55 s」来估后面机关的余量。

摆图读法，七条：

1. **电棒 =「你不动，它才动」。** 相位是世界时间的纯函数，按住方向 = 世界冻结 = 相位钉死：起步那一瞬是断的，整段穿越绝对安全；**真惩罚是中途松手**（0.08 s 缓冲后世界流动，人还在带子里就可能通电，接触即判直接死）。要么给「一步跨得完」的长度，要么明确接受「松手 = 死」。
2. **选型图 E3 那根 68 px 竖闸是示意尺寸，跳得过去（跳峰 136），别照它摆** —— 门形态必须顶天立地或 ≥ 144。
3. **挂高处的挡路棒会多出「蹲下钻过去」的绕路**（D29 交叉核对）：要么让碰撞体一直铺到地面，要么「要蹲」是你明确设计的第二解。
4. **危险物第一次出现**必须摆在「死了能立刻看懂为什么死」的位置；**电棒第一次出现放在祭坛之前**（无能力时它就是个普通计时陷阱，教「等时机」），过祭坛之后再出现一次（教「冻结钉住时机」）。解锁前后它是两种东西。
5. **刷卡门第一次出现**：让玩家先捡到卡再走到门 —— 光幕没有钢板落下来的实体威胁感，可读性全靠「琥珀锁 + 琥珀卡」一对颜色撑着。另外死亡重载后门关回、卡回原位：**刷卡门是死亡惩罚最重的节点**（白跑一段重取卡），摆它之前想好重跑距离。
6. **那一拍里尸体不算玩家**（D42）：刷卡门的感应带认不到它，所以**死在感应带里不会把卡白耗掉**（重载之后卡还在体内）；同理尸体不位移、不产生冻结意图、不推进任何吃世界时间的过程。要设计"死在这里会连带触发什么"，得先知道答案基本是"不会"。
7. **坠落带运行时是隐形的**（D52）：玩家看不见那条顶边线，"从哪儿开始算掉出去"全靠几何本身讲清楚 —— 网顶线以上必须是真能待人的地方，别指望画面补这一课。**一关一张就够**，只要 `width` 真盖过所有能走出去的边缘（多张不冲突，但每张都得够宽，漏一段就是那段没兜底）。反过来也别拿它当代偿：**"这个坑是死路"要靠尖刺/电棒说出来**，网只负责"离开世界"这一件事；一个既看不见又判得莫名其妙的死，跟没有底是同一类问题。

**相位器件（D69）的两条硬数**（它们不是危险物，但摆之前一样要先算）：

- **摇表成本**：`period 2.0 / duty 0.5` 这一档，最坏要摇满 **1.0 s** 才翻面（刚错过边界那一瞬）；地面跑速 260 px/s → 手按着走 1 s = **260 px**，落在 320 px 射程内 ⇒「吸住 → 跑着摇 → 等它翻面」做得完。锚只决定"世界冻着也能摇"，**不缩短这一秒**。`period` 调短 = 更省距离；`duty = 0.5` 是最坏档（越极端，最坏等待越短）。
- **穿梭块的 A / B 两点别压在危险物杀区上**（D66② 那条口径）：它整块瞬移、会把人留在半空，人掉下来的落点若在尖刺 / 电棒 / 残影杀区上，就成了"吸住它反而必死"；B 点尤其要查 —— 它常常是这条路上唯一的落脚点。

## 11. 已知坑

- **改过带 `class_name` 的脚本之后要重启编辑器。** 运行中的编辑器不会刷新 `class_name` 缓存（`scan()` / `reload()` 都不管用），依赖它的场景会报"标识符找不到"，而且这时候保存场景可能把新增的导出项写丢。游戏进程不受影响。
- 保存场景时，`@tool` 运行期生成的 `CollisionShape2D` 会被烘进 `.tscn` 成为 sub_resource。**无害** —— 装载时构件按导出项重算，导出项才是唯一真相。
- 关卡场景里**必须**有 `Player`（在 `player` 组）与 `PlayerSpawn`，否则 `LevelBase` 拿不到相机、玩家停在场景里的编辑期位置。
- 一个关卡只放一个 `AbilityAltar`：它是一次性的，第二次踩不发信号。（这条现在有守门：`verify_kit` 会计数，放两个直接 FAIL。）
- **祭坛只发信号，不开能力**：开启时机归 `LevelBase`（D28）。所以"踩上去没反应"先查两件事 —— 一是 `altar_path` 指没指到（节点挪过位置就要在检查器重指），二是关卡脚本有没有把基类的 `_begin_ability_sequence()` 覆盖掉却忘了 `super.` 调用。
- 钟摆没有碰撞体，别指望它挡路；要挡路用 `MovingBlock` 或地形。
- **出生点要有 30 px 站姿净空**（D27）：玩家以站姿碰撞盒生成，若 `PlayerSpawn` 压在低矮处，一开局盒子就陷进天花板，会被 `move_and_slide()` 顶出去。想让玩家一开局就蹲着，得让他先站在开阔处再自己按 S。
- **TileMapLayer 没有 `collision_layer` / `collision_mask` 节点属性（4.6 实测）**。碰撞层写在 TileSet 的物理层上（`lab_tileset.tres` 物理层 0 = layer 1 / mask 0），节点上只有 `collision_enabled` 能整层关。所以「哪层有碰撞」由「哪个源带碰撞多边形」决定：只有地形源带。
- **装饰刷在地形格上会消失**：`Decor` 的 z 在 `Tiles` 下面。要贴在地形表面的东西（警示条之类）刷在紧邻的**空格子**里，别叠在地形格上。
- **"指向另一个节点"的导出项必须用 `@export_node_path`，不能用 `export(Node)`。** 实测 4.6：`.tscn` 里给 `Node` 类型的槽写 `trigger = NodePath("../ButtonPlate")`，游戏进程 `instantiate()` 之后读回来是 `null`（`get("trigger")` 的 `typeof` 是 19 = NodePath，引用根本没被还原成节点）；而 `^NodePath(...)` 这种写法不是合法的文本语法，场景直接实例化失败。所以构件侧一律存 `NodePath`，**进树之后**再用 `get_node_or_null()` 解析 —— 相对路径在树外解析不了。以后再加同类槽位（比如"这个开关控制哪个机关"）照这条来，别再试 `export(Node)`。**要一个槽位装多台也一样**：用 `@export var triggers: Array[NodePath] = []`（活塞 D60 就是这么把"一块按两台"做出来的），`export(Array[Node])` 在同一个进程里读回来同样是空引用 —— 那条实测是针对单值的，列这一头没有理由行为不同，别拿它赌。
- **刷卡门 `key` 不接或接错类型**：运行时 push_warning「这扇门永远开不了」，`verify_kit` 也直接 FAIL。一卡一门：第二扇门引用同一张卡会被守门拦下（D30 第 6 条）。
- **别把 D53 那颗红灯当"走近了"的路标**（D53）：发红用的感应带与认卡是同一条 —— `sensor_reach` 让带子过门沿 24 px，按 `move_speed` 260 算只有 **0.09 s**，人几乎已经贴上光幕才亮。它的定位是"你马上就要撞上这扇不认你的门"的即时回执，不是远处警告；要提前提示得自己在更外面摆一块 `sensor_zone.tscn` 或直接给个视觉指向。**这条改动完全不碰刷卡链**（拒绝判据是 `is_held()` 那个 early return 之前的只读旁路），所以"红灯把门开了""红灯让门开不了"这类症状理论上不该出现，真出现了就是有人往 `_scan_denied()` 里写了副作用。想让它永远不闪：`denied_time = 0`。
- **`class_name` 脚本里的枚举不许用 Godot 原生类名**（D54 实测）：`enum Skin` 一句 `The member "Skin" shadows a native class` 就把整个脚本编译打掉了（3D 那个 `Skin` 资源类占着这名），而且报错会连带把赋值处一起打歪，看起来像两处的错。枚举改名 `SkinKind`、导出属性仍叫 `skin`。同族名字（`Node` / `Resource` / `Image` / `StyleBox`）都别拿来当枚举名。
- **能量卡那块"座子"不是新构件、也不是可摆的零件**（D55）：它是 `perch_idle` / `perch_taken` 那两张 D54 零件被 KeyPickup 直接 `preload`，跟着卡的状态自己换，**没有独立的节点、没有导出项、不用摆**。别为了"让座子更显眼"去给卡加描边或改原点 —— 选型图（`assets/props/preview_keyperch.png`）量过：座子对墙 cr=1.0（它在墙前面本来就隐形），"底座"读出来靠的是**轮廓分了两截**（对头顶那只 3.2、对地 1.9）。真嫌两截不够，旋钮是 `gen_props.part_perch(..., w=)` 那一档宽度（B=16 / C=20 已画在图里），改完要重 `--emit` 并新落两张零件，那是第二次裁定不是顺手改。
- **卡的可拾取提示是形状语言，所以它不吃时钟**（D55 的核心裁定）：不要给 KeyPickup 加 `TimeReceiver`、转角、浮动或任何"活一下"的东西。理由与鸭子不同 —— 彩蛋是房间里的摆件，卡是**你要走过去**的东西，而朝它走 = 按着方向键 = 世界必然冻结（D40/D41 那条地基），任何吃门控 delta 的提示都会恰好在最需要它的整段路上停住。`verify_kit` 钉着这三条。
- **彩蛋拿过就永久空座，只有主动重开才复位**（D54 裁定②）：这条与钥匙卡**故意相反** —— 钥匙死了掉回原地（D30 第 3 条）是因为它是机制素材、"重来"本身就是解谜的一部分；彩蛋是对"发现"的收据，复生就等于把房间重新藏回去假装没发生过。所以"玩家以为还能再捡一次"不是 bug。真要让某一类收集物复生，别去改 `collectible.gd` 的清单语义，另立一条并先回答"它凭什么是机制素材"。
- **危险物别手动改碰撞层**：判死区 layer 0 / mask 2 / monitorable false 是构件内置契约（§4），挪上 sensor 层守门会 FAIL，且起身净空查询会读不到它。
- **挡路的电棒别挂在半空**：下沿离地 ≥ 25 px 蹲着就钻过去了（§8a），看似挡路、实际形同虚设。要么铺到地面，要么明确当第二解。
- **一关不摆 `FallZone` = 坠落完全没有判据**（D52）。没有底的时候人会一路落到"下面恰好有什么"上 —— 而先接住他的多半是某个传感器，最常撞到的就是终点区：那条走 `restart_level()`、**清空进度**。所以症状长得像"复活代码坏了"（回到了出生点而不是存档点）。**先怀疑有没有那张网，再怀疑回档逻辑**；`fallzones=%d` 那一列只数不查，不会替你发现漏摆。
- **分组容器（`Terrain` / `Objects` / `Triggers`）一旦带 `position`，§2 那张表整列读数就全废了**（D65）：容器一动，它下面所有构件被整块平移，编辑器里那个"压住 y=0"的按钮运行时其实沉在别处 —— 而核对摆位用的读数正是那个已经不可信的数。这种偏差在编辑器里看不出来，只能由守门响：`verify_kit` 对**所有关卡**扫一遍，凡是"无脚本、还挂着东西的 Node2D"（= 真正在起分组作用的容器）位移不为 (0,0) 就 FAIL。族文件夹一律 `type="Node"`（裸 Node 没有 `position`，这条错在类型上就不成立），所以只有那三个根容器犯得起来。要整关挪位置就逐节点挪，别拿容器当平移把手 —— 那和上一条"别在运行时搬关卡根"是同一类事故。
- **别在运行时搬关卡根**（本次实测踩到）：节点进了树之后再改父级 `position`，**同一拍里 `Area2D` 的变换会跟着走、玩家刚体的变换还留在旧位置**，那一帧读到的重叠是假的 —— 危险物会凭空发一次 `touched_player`、人凭空被判死。编辑器里挪不触发（下一拍就同步了），但守门 fixture 里"把整个关卡抬到半空"必须在 `add_child` **之前**做。同理别拿"运行时挪一下父节点"当便宜手段去挪判死区。
- **凡是每帧自己走 `move_and_slide()` 的构件，都会把"平台速度"附加到站在他身上的人**（引擎行为，文档里找不到，D64 撞上的）。这条**对你只是写 `global_position` 传送的构件同样成立**，开关只在骑手那一侧（`platform_floor_layers` / `platform_on_leave`），而触发条件是骑手 `is_on_floor()` 为真 —— 你自己那侧 `velocity` 一直是零也不影响。实测签名很好认：**人以一个恰好等于「构件速度 ÷ 60」的常量位移被带走，同时 `vy = 0.00`、`is_on_floor() = true`**（活塞收回时拽着人每秒下沉 512 px 就是它）。两条出路：给骑手改 `platform_floor_layers`（**全局**开关，会连带改掉别的真平台构件 —— `MovingBlock` 就在这条线上），或**把根本不用速度的构件改成 `StaticBody2D`**。**先问"这块到底用不用 `velocity`"**：用不上的继承是纯风险，`piston_block` 今天就是按这条换的基类（它的位移一直是从伸出量直接落位置）。
- **净空在 15~30 px 之间那一档现在能自救了（D64②），但那是"能脱身"不是"能过关"**：站高 30 / 蹲高 15，所以这一档站着过不去、蹲着过得去，而"被上升的活塞顶着时蹲得下来"今天成立（`is_standing()` 认托举，见 §5 那行）。摆图时别把它当通路 —— 玩家得自己想到按下蹲键，画面上一寸提示都没有。**净空低于 15 px 仍然是死路**（他蹲着也塞不进去，那一档该由几何说话，别指望机制救）。

## 12. 瓦片地形（新关推荐）

模板 `Terrain` 下有三层 `TileMapLayer`，共用 `assets/tiles/lab_tileset.tres`：

| 层 | z | 碰撞 | 刷什么 |
|---|---|---|---|
| `WallFill` | -30 | 无 | `wall_fill` 一格背景填充，铺满所有空格子（背景墙） |
| `Decor` | -20 | 无 | 装饰大图（窗 6×4 格、灯 6×1 格、柜子 4×3 格……）与坑道 `shade` |
| `Tiles` | 0 | 有（TileSet 物理层 0） | 地形，terrain set 名 `solid` |

- **`level1.tscn` 那条"大文本场景 956.7 KiB"的编辑器警告是已知的，D50 已裁定暂存不修**（装载无可感代价，等真出现加载/保存卡手再动）。量出来的构成：其中 **77% 是 `WallFill` 那 47 256 格** —— 一个 264×179 的实心矩形、全用同一格图，而它无碰撞、纯背景；真正手摆的 `Tiles` 只占 214 KiB。所以要修就从「`WallFill` 改成存矩形 + 装载时填充」起步，另外三条候选（只关警告 / 拆子场景 / 转二进制 `.scn`）与各自的代价、还有一条"字节解码没自洽、别当规格用"的限制都在 D50。
- 地形用 **terrain 笔刷**（不是单格笔刷）刷 `solid`：踏面 / 竖面 / 底面按邻居自动出，角部自动包边。碰撞永远是整格矩形，美术描边只是画，不用为它对位。
- **坑**：坑的格子不刷地形；`WallFill` 照常铺满，再在 `Decor` 层给坑的格子刷 `shade`（半透明压暗）—— 坑读作「比地面暗一档的洞」。坑底那格刷地形，踏面自动出。
- **最小可通行缝隙在瓦片世界 = 48 px（3 格）**：16 的格刷不出 40，§8 第 4 条按 48 执行。其余 §8 约束（台阶 ≤32、缺口 ≤160、坑深 ≤96）不变。
- 悬空平台刷一行格子即可：上下左右四面会自动收边（踏面 + 底面 + 两端竖面）。
- **风格是数据不是代码，而且它是**两**个参数**：`tools/gen_tiles.py` 顶部 `STYLES` 存九套（`ab` / `a` / `b` / `c` / `d` / `e` / `f` / `g` / `g2`），`SHIPPED` 决定哪套占**没有后缀**的那组旧文件名（`tilesheet_terrain.png` / `tiles.json` / `lab_tileset.tres` —— 现有关与模板的 `ext_resource` 全按它写死，别改）。当前实装 **`g`（暗底夜光，D26）**。`EXTRA_SHIPPED`（D67）= 除了 SHIPPED 还要落盘的风格，产物一律带 `_<key>` 后缀：`d`（糖果贴纸）已经落成 `tilesheet_terrain_d.png` / `tilesheet_decor_d.png` / `tiles_d.json` / `lab_tileset_d.tres`。九套的预览图每次都会重出，选型不用重新画。**第二个参数是 `decor_set`（D70）**：一套风格除了调色板，还可以换一整张装饰词汇表（`PAINTERS` / `PAINTERS_GROVE`），缺省 `lab`。换的是**剪影**，条目名与占格一格不动，所以地形与共有装饰的瓦片索引仍然逐格同源。
- **给一关换配色（D67）**：复制模板 → 选中 `Terrain/WallFill`、`Terrain/Decor`、`Terrain/Tiles` → 三层的 `tile_set` 都指到 `res://assets/tiles/lab_tileset_d.tres`。三条要紧话：**① 三层必须指同一套** —— 混指会出现地基是夜光、地形是软糖，而守门只钉"模板那三层共用 `lab_tileset.tres`"，救不了你自己新关里的混指；**② 两套的瓦片索引逐格同源**（同一批 painters，只换调色板），所以从用 g 的关里**整层复制**已摆好的 `Tiles` / `WallFill` / `Decor` 过来照样对得上，一格坐标都不用改；**方向是单向的（D69 起）** —— d 的装饰比 g 多七件，把 **d 的 Decor 层复制进 g 的关**会掉那七块皮，`tileset_selftest` 现在钉"落盘那套的条目必须在每一套里都有、共有条目的矩形逐格相同"，红的就是这条；**③ 地形跟上了，构件还没跟上** —— 在册的青色系（祭坛核心、门光幕、LED 亮态）对 d 那面浅紫墙只有 **1.01~1.18**（对 g 墙是 5.05~6.04），深色门体反而从 1.39 涨到 4.29，主角从 2.63 涨到 15.70（那圈 g2 亮边在 d 上成了一条 1.09 的没用的淡边）。真要用 d 开一关，先裁一条「构件换色」的决定（要重烤 `gen_props.py` 那批 PNG、动 `props.json` 的别名、逐件验读法），否则玩家在那一关里看不出哪盏灯亮着。七个读数全在 D67。
- **手维护的第三份瓦片资源：`assets/tiles/level_02_tileset.tres`（D71，2026-10-27 起第二关用）**。它装的是**四张图集**：`sources/0..1` = g 的地形与装饰（清单产物原样），`sources/2..3` = d 的两张图集（**关卡作者自己在 TileSet 面板里加的，并手画了物理层**）。要紧的三句话：**① 这份文件不属于瓦片管线，`build_tileset.gd` 不认它** —— 正因为如此它不会被覆盖，但也**没有任何守门替它验碰撞与 peering**，画漏一格就是刷出来的砖没有碰撞、而四条无头全绿；**② 反过来，`lab_tileset.tres` 与 `lab_tileset_d.tres` 是纯产物**，往它们里手加源 = 下一次跑 `gen_tiles.py → --import → build_tileset.gd` 时被静默抹掉（D70 当天已经抹过一次），所以"要一份混合图集"唯一站得住的做法是**另存一份自己的 `.tres`**，就是这一份；**③ 源索引就是存档** —— 关卡的 `tile_map_data` 里存的是 `source_id`，所以这份文件里的 0/1/2/3 顺序一旦变动，已刷的砖会集体换图集；要动先动三层 `tile_set` 的指向，不要重排源。第二关那三层（`WallFill` / `Decor` / `Tiles`）指这一份，别一半指它、一半指产物。
- **`d` 那一套的装饰是「树丛」词汇（D70，`decor_set="grove"`）**：换风格那次留下的"装饰还是实验室件"这笔账这次还了，走的是**温室 / 废弃园区**那一档（机件构件一件没动，纯森林要先重开构件换色那条决定）。同名换剪影的十件：`pipe_h`=横卧的根、`pipe_v`=垂藤、`window`=石拱洞口、`light`=吊光盖菌、`monitor`=木巢箱、`led_panel`=贴壁地衣、`vent`=墙缝、`cabinet`=树桩、`cabinet_small`=岩石、`hazard`=荆棘带；多出来的七件：`moss_edge` / `leaf_cluster` / `mushroom` / `flower` / `bones` / `crate_wood` / `barrel`。**摆的时候三条只在这套里成立**：**① `moss_edge` 刷在台面上方那一格**（它是 Decor，在地形后面；画在那格的底部，所以"草长在台面上"要往上一格刷 —— 整格填满会读成一块悬空的砖）；**② `hazard` 现在是荆棘，它的动词是"从地里长出来"**，别再照 g 那版钉在墙上，离地一格就不像话了；**③ 亮底上光晕不承载信息**（`lip` 对白墙只有 1.22），所以那排吊灯说的是"这里有东西挂着"而不是"这里亮"，要读"亮"仍然得靠构件自己的青。
- **树丛套第二批八件（D74，`d` 的装饰从 21 涨到 29）**：`tree`（48×80，站着的树 —— 这套从前没有）、`ivy_patch`（48×32，贴墙的苔垫）、`vine_curtain`（32×48，从天花板垂下的藤帘）、`log`（64×32，落地的倒木，左端带断面年轮）、`fern`（32×32，站着展开的羽叶）、`moss_side`（16×32，`moss_edge` 的竖直版，贴坑壁/崖面）、`scree`（16×16，散落的碎石）、`web_corner`（32×32，墙角网，说的是"很久没人来"）。选型图 `tools/gen_grove_decor_preview.py` → `assets/tiles/preview_grove_decor.png`（十件候选里砍了 `puddle` 与 `leaf_litter`：前者 `glass` 对墙 1.03，**静止态就看不见**，不是冻结的问题；后者与 `moss_edge` 抢同一条踏口带）。**四条摆的口径**：**① 八件全在 `Decor` 层、零碰撞**，其中 `log` / `tree` 的冠 / `ivy_patch` 最容易读成"能踩"，别把它们摆在玩家会当踏板跳的落点上（与 `crate_wood` 同一档先例，手册 §5）；**② `vine_curtain` 与 `web_corner` 是"挂着的"**，画在格子顶部，要刷在贴着天花板那一格（不是它下方那格）；**③ `moss_side` 从格子左侧往外长**，贴坑的**左**壁时贴着刷、贴**右**壁时要另找一件（这套没有镜像件，摆反了就是苔从砖里长出来又倒着收口）；**④ 一件画完不许出自己的格**（图集重叠不报错，后画的盖掉前一件的皮 —— D70/D74 各踩一次，`tileset_selftest` 现在钉着这条）。
- **`d` 那一套的亮度档（D72，整条 ×0.90；2026-10-28 从 ×0.80 回调）**：d 原样画面均值 205、墙相对亮度 79.1，而冻结那层 CRT 是等比乘 1.3 再夹 255 —— 亮底没有余量给它，**45.7% 的像素会撞天花板**（色相与细节一起没）。现在墙 62.1 / 均值 185.2 / 冻结削顶 32.0%：这是他在"亮"与"细节"之间自己称过两次的结果（先挑 B 太暗，2026-10-28 试玩后回到 A），**别再顺手调档**。三条摆图口径：**① 要再调亮度只动 `STYLES["d"]` 那 15 个颜色键，且乘数作用在 `gen_d_dim_preview.ORIGINAL_D` 那份原样字面量上**（当前值 = 原样 ×0.90；在已降亮的值上乘系数会二次舍入，落盘就不再等于选型图里那一行）—— `tools/gen_d_dim_preview.py` 一跑就出五档对比图与读数，图与出货同源；**② `pickup` 永远不跟着缩**（它跟 `key_card.png` 那张实物零件同色，是语义不是风格 —— 缩它等于让告示牌指一张不存在的卡）；**③ 亮度降了不等于构件读得清**：墙往下走时**比墙暗的构件变差、比墙亮的构件变好**（在册真色对三档墙：主角 15.70→**12.54**(A)→9.91(B)、深色门体 4.29→**3.43**→2.71、门 LED 亮态 1.01→**1.27**→1.61、琥珀 1.34→**1.07**→1.18）。A 档比 B 档少欠一点，但"构件在亮底上读不读得清"这笔账得走 D67 裁定③的"重开构件色"，不是走亮度档（全表见 D72 节末订正）。
- **两块无字告示牌（D56，`Decor` 层）**：`sign_card_arrow`（32×16 = 2×1 格，实心琥珀卡 + 亮白右箭头）说的是「往那边走，那里有一张卡」，`sign_card`（16×16 = 1 格，只有那只卡）说的是「这扇门要的是这个」。牌面上一个字都没有，两句全靠形状与颜色：琥珀自 D29 起专指可拾取，白只说方向 —— 所以白箭头不会被读成第二只卡，卡也不会被读成门楣那颗 LED。**那只卡的颜色走 `p["pickup"]`，不走本套的 `accent2`（D69）**：`key_card.png` 是照落盘那套的 `accent2` 烤的，牌要跟着风格一起换色就会指错东西（d 的 `accent2` 是粉，牌与卡 cr 只有 1.47）。三条要记：**① 它是装饰格，不是构件** —— 无碰撞、无导出项、不吃任何时钟（冻结与否都照原样立在那儿），摆哪一格纯看你要指哪；**② 和所有装饰一样刷在空格子里**，叠在实心地形格上会被地形盖掉（§12 上面那条坑同源）；**③ `Decor` 在 z=-20**，牌永远在那面墙上、主角身后，不会挡人。要**左向**箭头没有现成格：`TileMapLayer` 不能逐格翻转，得回 `tools/gen_tiles.py` 给 `SIGN_SIZE` / `sign_plate` 加一个 kind、`DECOR` 加一行，再跑下面那条管线。
- 改图集的管线（一般用不到，改风格才碰）：`py tools/gen_tiles.py` → `--import` → `--script res://tools/build_tileset.gd` → `tileset_selftest`。**一次跑就把 `SHIPPED` + `EXTRA_SHIPPED` 每一套都重出**，`build_tileset.gd` 也一次出两份 `.tres`（一对清单一份产物，见 D67），不用改常量来改去。**但只改了一套的清单时，用 `-- --only=lab_tileset_d` 只重建那一份**（D74 加）—— `lab_tileset.tres` 现在是关卡作者**手改过的工作区文件**（graft 了 d 的图集 + 手画碰撞多边形，没有第二份），整跑一遍就连它一起重写掉。生成器落盘前先跑 `check_decor_rects()`（D69）：装饰矩形必须 16 对齐、不出界、**两两不重叠**、painters 与条目对得上 —— 摆重叠了不崩，只是后画的那件盖掉前一件，而清单里仍然记两块。预览图 `assets/tiles/preview_room_g.png` / `preview_room_d.png` 是从图集逐格拼的，和引擎同一条合成路径，所见即所得；`preview_tiles.png` / `preview_tiles_d.png` 是两套各自的图集放大图，底下那条带是**现有构件的占位色落在新地砖上**的兼容性对照（换风格要看的就是这一条，不是地形自己）。生成器每次跑还会打印一张九套风格的 WCAG 对比表（主角 silhouette 对墙低于 4.5 会标出来，D26 第 8 条）。
